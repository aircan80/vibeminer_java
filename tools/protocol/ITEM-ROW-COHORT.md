Live operation requires separately authorized `--live`; normal verification is offline.

Prior archive total/offset and loose total are enforced against fresh strict exact-range responses.

Fixed global ceilings are **4 MiB response-body wire, 512 requests, 8 MiB aggregate decoded work, 4 MiB per encoded/decoded chunk buffer and 120 seconds**. Both fresh BLTE headers are authenticated first. Before metadata/index bodies, actual complete selected chunks are deduplicated and preflighted for Item metadata/main zero-key section and Sparse metadata/full zero-key suffix. Fresh metadata must match pinned coordinates. After physical ID/copy lookup, a second preflight checks only complete chunks intersecting selected Sparse records. No other section or fallback is requested. Failed reservations remain conservative; exceeding any limit stops without widening scope. Buffers include bounded exact section/index windows in addition to transient encoded/decoded chunk arrays; the buffer cap is not a total heap cap.

Fixed IDs/copies accept a physical record or a unique copy with a direct physical source. Sparse lookup additionally requires validated complete maps/IDs/copy coherence. Unresolved fixed copies are scoped unsupported. Sparse names follow the actual ordered candidate string prefix through its fifth localized field, using record-bounded strict UTF-8 C strings, not a guessed byte offset. Numeric fields use matching candidate binding and validated physical storage; unsupported storage or invalid values stop.

`PRIVATE ROW` lines may contain readable names and projected values for private QA. **Do not publish the complete stdout log.** `PUBLIC ROW` lines contain only IDs, coverage/status, physical source/copy facts and name SHA-256/count, never actual record names or integer contents. Candidate provenance and transfer receipts are nonpayload metadata. No content is persisted by the program. This proves only consumed header/chunk bytes and the selected projection: full table CKeys remain unverified, other keyed sections' readability remains unknown, trailing Sparse fields and generalized row/schema/search support remain unclaimed.

The offline fixture suite covers real bundled resource loading, schema gates, variable string prefixes, copies/absence, chunk corruption, source identity, UTF-8 failure, staged request/wire/decode/buffer/time/cancellation refusal and output redaction. Synthetic success does not establish live compatibility.
