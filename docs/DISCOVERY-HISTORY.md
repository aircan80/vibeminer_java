# Exact discovery observation history

**Approved planning contract for [#92](https://github.com/aircan80/vibeminer/issues/92), under #18/#4. Not implemented. Implementation requires #91 qualification and explicit authorization.** This records metadata the application actually observed; it is not an archive of available game content, a complete historical catalog or broader #18 completion. No game-install reads, community catalog imports, arbitrary config entry, background refresh or acquisition integration are included.

## Events, snapshots and provenance

One observation event identifies a successful explicit client retrieval batch of the official product versions and CDNs documents. These are two independently timed responses, not an atomic upstream snapshot. Preserve each actual HTTPS source URL, capture time, SHA-256 and length; event completion time is a separate observation. A new successful retrieval gets a new event UUID even when timestamps and body bytes happen to match. Replaying the same captured event UUID is an idempotent repository write, not another retrieval.

Existing `BuildSnapshot.snapshotId()` remains unchanged: raw product/channel/region/version, build/CDN configuration identities, upstream BuildId, ProductConfig and fixture boundary establish its identity. Friendly labels, retrieval times, source document bodies and CDN route changes do not replace this identity. A→B→A produces three observation events and two snapshot identities. The same snapshot may have different event-specific source documents and CDN hosts on later retrievals.

Canonical snapshot provenance remains its first registered provenance. History must not update `snapshot_sources`, saved workspace evidence, original source receipts or previously recorded observation times. A selected event returns that event's evidence, never a canonical-first snapshot's older documents relabeled as the chosen retrieval. Workspace lifecycle and labels are independent; deleting a workspace cannot silently erase history or shared documents.

Use “Observation history,” “Previously observed” and “Recorded at.” Local event ordering and publication `seqn` values do not establish game-build age, upstream chronology or current availability. Keep raw product identities separate, preserve the existing Published channel label, and do not infer current/preload channels or marketing editions from unrelated summary flags. Remote content availability is explicitly NOT_CHECKED in this slice. Selecting metadata does not download, check availability or prove that an older build is currently obtainable.

## Minimal layered boundary

Application values compose existing `BuildSnapshot` and `SourceDocument` records. Nested records may keep the API small; no infrastructure parser, URI, JDBC, filesystem or presentation types cross the ports.

- `DiscoveryParsedSource(source, columns, sequence)` preserves ordered parsed column names and optional raw sequence text. Leading zeroes remain significant raw facts. Original header type/width descriptors remain in the captured bytes.
- `DiscoveryObservedBuild(build, versionsRowOrdinal, versionsValues)` preserves every selected versions-row column, including unknown/empty values and original hex case. The ordinal is zero-based across all parsed nonempty, noncomment data rows before region filtering, not a text line number. Duplicate rows with the same snapshot identity remain distinct references.
- `DiscoveryCdnRow(rowOrdinal, values)` preserves the selected CDN row once per event. Its raw Name must exactly match the requested region; replay the existing requirement for exactly one usable region match rather than choosing a first match. Preserve route fields without executing them or requiring acquisition-supported ConfigPath/HTTPS Servers. Valid history may have an unsupported download route.
- `DiscoveryEvent(eventId, productId, region, completedAt, parserRevision, versions, cdns, selectedCdn, builds)` binds exactly two role-named documents, selected-row interpretation and their event-specific builds. Build evidence must match these source receipts and normalized protocol identities. Raw maps retain original values while normalized snapshot keys remain normalized. Codecs traverse the explicit column order rather than unspecified map iteration order.
- A bounded `DiscoveryObservationGateway.observe(productId, region, cancellation)` returns the exact captured event. Factor the existing combined response operation to produce that value directly. Never implement it as `refresh()` followed by reading the shared diagnostic `lastObservation` reference: concurrent refreshes can replace that reference. Cancellation must reach both existing bounded versions/CDNs futures with bounded waiting.
- `DiscoveryHistoryRepository.append(event, limits, cancellation)` atomically publishes a verified event; bounded list and read operations provide summaries and detail. Identical event UUID plus identical immutable facts is idempotent. The same UUID with changed source bytes, URL/time, completion time, selected rows or interpretation is an immutable-event conflict.
- `DiscoveryHistoryService.refreshObservation(productId, region)` returns a small `RefreshOperation` with read-only `completion()` and `requestCancellation()`. History list and selection are separate asynchronous retained-only operations. Selection identifies event UUID, snapshot ID and versions-row ordinal, resolving duplicate snapshot rows without guessing. It rereads the chosen event and returns its original documents, row maps, CDN context and NOT_CHECKED remote availability.

The service bounds actual jobs to four until source/transaction retirement, then completes results outside its monitor so callbacks can admit their next operation. Failed, malformed or canceled pre-commit refreshes publish no partial event. If append commits before cancellation wins, return the actual committed event; do not recheck cancellation afterward and claim rollback. A compatibility `DiscoveryService.refresh` projection, if retained, must map this same returned event rather than a shared last-observation reference or canonical-first provenance. Canceling a derived observation future cannot erase a committed event. No startup or history-selection operation refreshes remote pointers.

## One catalog and shared bytes

Use one additive migration in the existing shared catalog; allocate the actual next schema version at implementation. Reuse `source_blobs` for raw metadata SHA-256 deduplication and existing snapshot identities. Add an event header with persisted local sequence/counts, two role-specific document receipts, one bounded checked CDN-row interpretation and ordered event-build references with checked parsed-row facts. Event codecs store document references rather than repeated body arrays. Both document roles may reference the same digest while preserving their separate retrieval receipts.

One IMMEDIATE transaction validates pinned parser revision and transport-free source replay, checks an existing event UUID for exact idempotence, computes quotas, registers immutable snapshot identities and writes all event receipts/references. Check cancellation before commit. Any insertion, quota or validation failure rolls back new headers, blobs, snapshots and references together. An existing idempotent event must still pass integrity/replay checks before returning, including when storage is already above quota.

Validate actual shared bytes and length against their digest before relying on an existing blob; INSERT OR IGNORE alone is not an integrity check. Do not overwrite, heal or evict already referenced evidence. Expected counts, ordinal ordering and checked parent references must prevent missing rows or blobs from silently becoming an empty successful event. Unknown parser revisions return UNSUPPORTED_INTERPRETATION, never an automatic reinterpretation under new semantics. One shared transport-free mapper can validate columns, sequence, row maps, CDN ambiguity and normalized snapshot fields for both ingestion and selected detail.

Bound memory as well as storage: detail loads each distinct raw digest once, constructs exactly two role-specific `SourceDocument` objects and shares those same objects across every event `BuildEvidence`. Avoid calling the existing eager canonical `readSnapshot` once per row: that hydrates unrelated first-observation bodies repeatedly and can expose the wrong event's evidence. Use a narrow identity-column check without canonical body hydration. Cache each role's defensively copied bytes once for parser replay rather than cloning per build. The canonical-first result from `ensureSnapshot` must not substitute for the chosen event's build.

Summary pages contain bounded identities, receipt descriptors, selected-row references and raw labels, never raw document arrays. Check summary/header/reference codecs and hashes, but do not represent an unreplayed summary as selected or acquisition-ready evidence. Detail and selection reread one coherent complete event, verify bodies and replay interpretation; a summary is not authority for selection.

## Limits, pages and failures

Initial product limits are exactly two documents of at most 1 MiB each, at most 64 matched build rows per event, 10,000 events, 100,000 event-build references and 256 MiB of table-global unique raw metadata bodies. Page size defaults to 25 and is capped at 100. Existing parser bounds remain: 64 columns, 10,000 data rows and 16,384 characters per data line. These are supported product limits, not upstream protocol guarantees; a valid larger batch can receive an explicit limit refusal.

The 256 MiB byte quota sums actual unique body lengths across all `source_blobs`, including preexisting workspace documents. Charge a shared body once. If existing bodies already exceed that limit, a zero-new-body event may still be appended when event/reference quotas fit; any positive new bytes beyond the limit are refused. Event/reference/interpretation overhead is separately bounded by count and codec limits. This is not a total database, filesystem or disk-use budget. Concurrent quota checks occur inside the same write transaction with checked arithmetic. No automatic pruning or evidence eviction is allowed; future pruning requires explicit reference accounting.

Pages sort by a persisted, unique, increasing local event sequence, not source wall time. A cursor binds the exact filter, upper sequence watermark and before-sequence position, with no process epoch. Repeated timestamps and backward wall clocks remain legal recorded observations; do not clamp them or infer age. Stable pages exclude later appended events until an explicit new history query.

Typed failures distinguish invalid requests, busy/closed service, no matching event, QUOTA_EXCEEDED, per-operation limits, CORRUPT_OBSERVATION, immutable-event conflict, unsupported interpretation and storage failure. If retrieval succeeded but persistence failed, report explicitly that the observation was not saved with its precise cause. No history is a genuine empty list; missing required documents or corrupt references are failures, not fabricated empty history. No arbitrary hash/config lookup or latest-pointer substitution can produce a selectable event.

## Contract-first verification

Start with immutable values and narrow ports, then additive repository and shared pure observation mapping, followed by service, runtime and bounded history UI. No implementation follows from this planning document without explicit authorization.

Required offline tests cover A→B→A; same-version/different-config identity; same UUID idempotence versus changed facts/conflict and new UUID/same bytes; shared body storage with distinct receipts; duplicate selected rows; raw optional/unknown/empty columns, ordered headers, sequence text and hex case; product/region/channel isolation; original workspace proof preservation; restart/migration; concurrent quota admission; missing/corrupt document, parent or row-map records; unsupported parser revision; halfway transaction failure and late pre-commit cancellation rollback; idempotence above quota and zero-new-body events above the byte cap; stable bounded pages with no bodies; 64-reference detail sharing the same two source objects; commit-aware cancellation; and selection with forbidden transport. Native authored-data checks must show explicit prior-observation labels and remote “Not checked,” with no acquisition or chronology claim.
